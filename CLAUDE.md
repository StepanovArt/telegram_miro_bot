# Telegram → Miro Inbox Bot

## Что строим

Личный Telegram-бот. Я пишу текст или наговариваю голосовое → бот
создаёт стикер в зоне высадки на моей доске Miro. Вечером я прихожу
на доску и вручную растаскиваю стикеры по местам (там мой календарь).

Бот — это **быстрый захват**, а не система управления задачами.
Осмысление делаю я руками на доске.

## Стек

- Python 3.11+
- `python-telegram-bot` (v21+, async)
- `requests` для Miro REST API
- `google-genai` для транскрипции голосовых
- `python-dotenv`

Никаких БД, ORM, Docker и веб-фреймворков. Один файл `bot.py` +
`.env` + `requirements.txt`. Если файл переваливает за ~250 строк —
значит что-то переусложнено.

## Переменные окружения

```
TG_TOKEN=
MIRO_TOKEN=
MIRO_BOARD_ID=
GEMINI_API_KEY=
ALLOWED_USER_IDS=123456789
```

`ALLOWED_USER_IDS` — список целых через запятую.

## Поведение

1. Приходит сообщение (текст или голосовое)
2. Если `from_user.id` не в whitelist → игнор, лог WARNING с id и username
3. Голосовое → скачать → транскрибировать через Gemini
4. Текст → взять как есть
5. Создать стикер в Miro
6. Ответить `📌 На доске`
7. При ошибке → ответить `⚠️ Не долетело: <причина>` и залогировать

## Требования по безопасности

**Это приоритет №1. Бот публично находим в Telegram, любой может
нажать /start.**

- Whitelist через `filters.User(user_id=[...])` на уровне регистрации
  хендлеров, НЕ проверкой внутри функции. Так защиту невозможно
  забыть добавить в новый хендлер.
- Если `ALLOWED_USER_IDS` пустая или невалидная → бот НЕ стартует.
  Fail closed, не fail open. Падать с внятным сообщением.
- `.env` в `.gitignore` до первого коммита.
- Простой rate limit: не больше 60 сообщений в час. Защита не от
  чужих, а от моего же кривого цикла при отладке, который выжрет
  квоту Gemini за минуту.

## Miro API

Эндпоинт:

```
POST https://api.miro.com/v2/boards/{board_id}/sticky_notes
Authorization: Bearer {MIRO_TOKEN}
```

Тело — вложенная структура. Плоский JSON вернёт 400:

```json
{
  "data":     { "content": "текст", "shape": "square" },
  "style":    { "fillColor": "light_yellow" },
  "position": { "x": -2000, "y": 0 }
}
```

Гочи:
- `MIRO_BOARD_ID` часто заканчивается на `=`. Это часть ID, не мусор.
  При подстановке в URL может понадобиться `urllib.parse.quote`.
- Токен привязан к команде, а не к доске. `404` = доска в другой
  команде, а не «неверный ID».

## Позиционирование

Зона высадки — слева от календаря, `x = -2000`.

`y` вычисляется из времени суток: `(секунды с полуночи) / 10`.
Никакого состояния между запусками, и стикеры сами ложатся сверху
вниз в хронологическом порядке — утренние выше, вечерние ниже.

Не заводи счётчик, не храни позицию в файле.

## Голосовые

Скачивание из Telegram — ДВА шага, не один:

1. `getFile` по `file_id` → получить `file_path`
2. Скачать с `https://api.telegram.org/file/bot{TOKEN}/{file_path}`

Дальше `.ogg` (opus) идёт прямо в Gemini — **Whisper не нужен**,
Gemini принимает аудио напрямую. Модель `gemini-2.0-flash`.

Промпт транскрипции:

```
Transcribe this audio. Return ONLY the transcription as a single
short line suitable for a sticky note. No preamble, no quotes,
no formatting. If the audio contains a task, phrase it as a task.
```

Язык не задавать жёстко — я говорю и по-русски, и по-английски.

Файл удалять сразу после отправки в Gemini.

## Обработка ошибок

Ни одна ошибка не должна ронять бота — я должен видеть проблему
в чате, а не в логах на сервере.

- Miro вернул не 2xx → показать статус и тело ответа в ответном
  сообщении
- Gemini не ответил → сохранить исходный текст «🎤 голосовое,
  транскрипция не удалась» и всё равно создать стикер
- Таймауты: 10 сек на Miro, 30 сек на Gemini

Принцип: лучше стикер с плохим текстом, чем потерянная мысль.

## Запуск

`polling`, не webhook. Никакого домена, TLS и nginx.

Важное свойство polling: если бот не запущен (ноут спит), Telegram
держит сообщения у себя примерно сутки и отдаёт их при старте.
Это встроенный буфер, поэтому БД для очереди не нужна.

Деплой — `systemd` unit на VPS, но это потом. Сначала локально.

## Чего НЕ делать

Явные не-цели. Если появится соблазн — не надо:

- База данных, миграции, SQLAlchemy
- Категории, теги, приоритеты, статусы
- Редактирование и удаление стикеров через бота
- Картинки и файлы
- Инлайн-кнопки и меню
- Webhook, FastAPI, Docker
- Умная раскладка, кластеризация, автогруппировка
- Поддержка нескольких пользователей

Всё это ломает главное свойство: захват должен занимать секунду.

## Приёмка

Собирай по шагам, каждый проверяй отдельно. Не пиши всё разом.

1. Текст → стикер появился на доске
2. Чужой user_id → ничего не произошло, в логах WARNING
3. Пустой `ALLOWED_USER_IDS` → бот не стартовал
4. Голосовое → транскрипция читаемая, стикер на месте
5. Битый `MIRO_BOARD_ID` → в чате внятная ошибка, бот жив
6. Три сообщения подряд → три стикера, не перекрывают друг друга

## Стиль

- Показывай диффы перед применением
- Комментарии по-русски, код и имена — по-английски
- Без класса-обёртки ради обёртки: модуль с функциями достаточно
- Логирование через `logging`, не `print`
